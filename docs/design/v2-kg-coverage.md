# v2 KG 커버리지 캔버스

2026-09-09 · 기준 `ee51355` · 작업 브랜치 `codex/v2-kg-coverage`

> **편입 메모(2026-09-11)** — 이 구현은 개념 탐색의 **이웃 탐색** 모드(`kg_view=explore`)로 병합했다.
> API는 `GET /kg/{kg}/explore`(아래 본문의 `/kg/{kg}/graph`는 이 경로를 뜻한다)이고, 기본 그래프 모드는
> v1 문서군 hull 캔버스(`GET /kg/{kg}/graph`, [ARCHITECTURE_V2.md](../ARCHITECTURE_V2.md))가 맡는다.
> `/kg/{kg}/concepts/{cid}`, `/concepts/{cid}/mappings`, `/series?document_version_id`는 그대로 수용했다.

2차 평가에서 확인한 코어·제품 디자인을 유지하며 개념 탐색에 그래프를 추가한다.
도메인 KG는 사람이 발행한 리비전에 고정된다. 문서 매핑 상태를 조회해도 개념이나 관계를 자동 생성하지 않는다.

## 탐색과 표시 범위

- 기존 파란색·제품 토큰·탭 순서를 유지한다. 개념 탐색에서 **그래프 / 목록**을 전환한다.
- 기본 그래프는 개념 페이지에 포함된 관계를 그린다. **선택 개념 주변**은 양방향 한 단계 이웃을 조회한다.
- 페이지당 개념 최대 30개와 별도 중심 개념 1개, 관계 최대 120개다. 누적해서 전체 KG를 브라우저로 가져오지 않는다.
- 레벨과 ID로 위치를 결정하며 커버리지 재조회가 배치를 바꾸지 않는다. 25~200% 확대, 스크롤·빈 공간 드래그를 지원한다.
- 화살표는 저장된 관계 방향이다. 상하위 관계는 실선, 기타 관계는 점선이다. 관계명은 툴팁과 상세 목록에서 확인한다.
- 다부모·기타 관계 순환을 지원한다. 조밀한 페이지에서는 중심 개념의 관계를 우선 표시한다.
  120개 상한에 도달하면 안내하고, 선택 개념의 페이지화된 관계 목록으로 나머지를 확인한다.
- 노드 클릭 또는 Enter/Space로 상세를 연다. 목록의 다른 페이지에 있는 개념도 단건 조회로 편집할 수 있다.
- `kg`, `concept`, `graph_focus`, `coverage`, `kg_view`를 URL에 보존한다. 페이지 이동은 기존 커서 이력으로 관리한다.

## 커버리지의 의미

문서 목록에서 **문서 버전 하나**를 선택하거나 원본 탭에서 선택한 버전을 사용한다.
문서군 자동 분류와 집계 모델은 아직 이행되지 않았으므로 v1의 문서군 hull을 그대로 복제하지 않는다.
새 기능은 선택한 문서 버전의 여러 템플릿·규칙이 고정 도메인 KG에서 차지하는 범위를 보여준다.

| 표시 | 집계 기준 |
|---|---|
| 승인 / 검수 / 반려 | 적용 건·규칙별 최신 검수 리비전의 상태와 연결 개념 |
| 발행 시리즈 | 해당 최신 매핑을 사용한 적용 건의 현재 `published_run_id` 중 `ready` 시리즈 수 |
| 미연결 | 해당 KG·문서 버전·개념에 최신 검수 규칙이 없음 |
| 문서 미선택 | 커버리지를 조회하지 않은 상태 |

리스트 항목 수나 과거 재추출 수로 규칙 수를 부풀리지 않는다. 시리즈 수는 원자 값 출처의 중복 제거
개수가 아니며 문서 전체 커버리지 비율도 아니다. 같은 원본을 다른 목적으로 추출한 시리즈는 각각 표시한다.
다른 KG 리비전의 규칙을 같은 개념 ID라는 이유로 합산하지 않는다.

새 문서 버전이 등록되어도 명시한 과거 버전의 커버리지는 유지되고 **과거 버전**으로 표시된다.
기본 소스 조회는 계속 현재 문서 버전만 사용하며, 버전을 명시한 소스 조회만 그 버전으로 제한한다.
승인 취소나 새 검수로 발행이 무효화되면 발행 표시도 해제된다.

선택 개념의 **검수 규칙 → 원본 검수**, **발행 출처 → 추출 결과**는 문서·버전·템플릿 적용 건·
매핑·시리즈 식별자를 전달한다. 예전 화면에서 남은 문서 식별자로 이동하지 않는다.

## API와 권한

| API | 계약 |
|---|---|
| `GET /kg/{kg}/graph` | `focus_id`, `q`, `document_version_id`, `cursor`, `limit≤30`; 노드·관계·생략 표시·선택 문서 버전. Pydantic 응답 모델 |
| `GET /kg/{kg}/concepts/{cid}` | 선택한 리비전의 개념 단건 |
| `GET /kg/{kg}/concepts/{cid}/mappings` | `document_version_id` 필수, 최신 검수만 커서 조회 |
| `GET /series` | 선택적 `document_version_id` 추가. 기존 기본 조회 의미 유지 |

기본 KG 탐색은 reader를 호출하지 않는다. 커버리지는 선택한 문서 한 건의 `authorize`를 확인하고
저장된 메타데이터만 집계한다. 셀 읽기·뷰포트 렌더·전체 문서 스캔은 하지 않는다.
권한 거절/만료는 오류이며 미연결 0건으로 바꾸지 않는다. 문서 선택을 해제하면 고정 KG 탐색을 계속할 수 있다.
그래프의 노드·관계·커버리지는 하나의 SQLite 읽기 스냅샷에서 조회한다.

## 검증

- 백엔드: 다부모·순환·조밀한 관계·노드/관계 상한·커서 필터 검증, 최신 검수와 재추출 집계,
  다중 템플릿, 문서 버전 고정, 승인 취소에 따른 발행 무효화, 접근 거절, 셀 읽기 미수행.
- 컴포넌트: 다른 페이지 노드의 키보드 선택·개별 상세·원본 검수 이동, 확대 시 추가 요청 없음,
  권한 오류 후 문서 선택 해제.
- Playwright: 실제 캔버스 드래그·확대·이웃 페이지·키보드·딥링크, 기존 전체 추출/DB 흐름에
  커버리지 확인·검수 복귀 추가. 실제 실행 결과는 해당 커밋의 GitHub Actions에 기록한다.
- 외부 Chromium 경로는 [E2E 실행 안내](../../e2e/README.md)의 환경변수로 지정할 수 있다.

## 실제 DRM PoC에 필요한 입력

현재 실행 환경에는 제품 DRM SDK, `KG_V2_READER_FACTORY`, `KG_V2_READER_REVISION` 설정이 없다.
`reader_probe`는 렌더 계약 점검 도구이며 실제 SDK 연동·추출 정확도·원본 충실도 검증 완료를 뜻하지 않는다.

실제 어댑터 작업에는 **DRM 제품명·버전, 승인된 SDK/API 문서와 실행 환경,
해당 계정에서 읽을 수 있는 테스트 문서 참조**가 필요하다. 자격증명은 서버의 보안 설정으로 제공한다.
네이티브 렌더 좌표와 병합·스타일·이미지·차트·수식 표시, 여러 시트 값/출처, 권한 만료와
읽기전용 동작을 승인된 환경에서 확인한다. PDF 프리뷰는 이 PoC의 범위에 포함하지 않는다.

문서군 hull/자동 제안·레시피 이식, v1 마이그레이션, watch/재크롤링,
PostgreSQL+AGE, DVC, 겹친 템플릿 동시 overlay는 별도 후속 범위로 유지한다.
