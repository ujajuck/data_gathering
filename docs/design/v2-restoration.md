# v2 기능·디자인 복원 기록

2026-09-09 · `codex/db-schema-redesign`

DB 구조를 개선하면서 기존 제품의 이름·색·탭 순서를 변경할 필요는 없었다.
별도 v2 화면을 작성한 과정에서 디자인이 달라지고 일상 기능이 빠졌다.
이번 변경은 기존 제품 표현을 공유하고, v2의 불변 버전·출처 모델 위에 해당 기능을 복원한다.

## 디자인 기준

- 제품명과 브라우저 title: **Semantic Excel Integration**.
- 순서: **1. 파일 분석 → 2. 개념 탐색 → 3. 원본 데이터 → 4. 통합 DB → 5. 템플릿 관리**.
- 기존 파란색 `#3569e8`, 13px 본문, 채움형 탭, 기존 배경·테두리·글꼴을 유지한다.
- `frontend/src/product.ts`와 `product.css`를 v1/v2에서 공유한다. CSS 스코프는 충돌 방지를 위해 유지한다.
- 작업별 패널·페이지·원본 뷰포트는 v2 데이터 구조를 사용한다. v1 화면 전체를 그대로 옮겼다는 의미는 아니다.
- 기본 진입은 v2다. `?v1=1`은 **이전 데이터** 화면이며 `kg.db`를 사용한다. v2의 `v2.db`와 혼용하지 않는다.

## 복원·개선 범위

| 항목 | 현재 동작 |
|---|---|
| 문서 필터·정렬 | 작성자·작성일 범위·접근/추출 상태·적용 템플릿·이름 검색, 문서명/작성자/작성일/등록일 양방향 정렬. 필터·정렬별 keyset 커서 |
| 접근 상태 | 사용자별 마지막 권한 관찰을 표시. 목록에서 모든 원본을 열지 않으며 열기·추출·다운로드 때 재확인 |
| 검수 큐 | 파일 분석 하단에서 대기/승인/반려 모아보기, 승인/반려, 해당 원본·매핑으로 이동 |
| 검수 이력·복원 | 규칙별 과거 버전을 페이지로 조회. 현재 edit_seq를 검사하고 과거 내용을 새 리비전으로 복원 |
| 개념 트리 | 펼친 하위 노드만 조회. 상위 체크는 서버에서 접힌 자식까지 선택. 제외·부분 선택·다부모 중복 처리. 체크 재조회 중 펼침·페이지 유지 |
| 소스 일괄 추가 | 선택 개념의 발행 소스를 페이지마다 읽고 중복 제거. 진행 표시·취소·100필드/필드당 100소스 제한 |
| 개념 단건 편집 | 이름·설명·별칭 추가·관계 추가/제거·폐기/복원. 최신 KG를 CAS로 검사하고 새 전체 스냅샷 발행 |
| 전처리 프리셋 | 원값 유지/자동 정규화/작업 공간 `config/normalizers.yaml`. 문서 규칙 또는 공통 템플릿 규칙에 고정 |
| 템플릿 내보내기 | 선택한 발행 버전의 실행 JSON 다운로드 |
| DB 다운로드 | SQLite와 UTF-8 BOM CSV. `_record_key`에 `LOT-001` 같은 업무키 표시. `_row_key`와 lineage 키는 보존 |
| 검수 안내 | 규칙 없이 셀 선택 시 “먼저 추출 규칙을 선택하세요.” 표시 |
| 오류 | 출력 타입·단위 불일치에 기대/실제 값 표시. 원본 단위와 목표 단위의 불일치도 설명 |
| API 계약 | POST 요청을 Pydantic 모델로 정의. `/docs`에서 필수 request_key·위치 범위·작업 state enum 확인 |
| 회귀 검증 | Vitest 30초 timeout, 백엔드/컴포넌트 테스트 추가, `e2e/v2`와 GitHub Actions 추가 |
| 문서군 제안·레시피 이식 | 등록 시 구조 서명(시트명·헤더 라벨·병합 범위) 캐시. 파일 분석에서 같은 양식으로 보이는 적용 문서를 점수순으로 제안하고, 선택하면 시트 역할을 이름으로 맞춰 head 매핑을 `candidate/proposed` 리비전으로 이식(자동 승인 없음) |

복원은 이미 생성된 추출·DB 산출물을 덮어쓰지 않는다. 이전 DB 파일에는 `_record_key`가 없을 수 있으며
새로 생성한 빌드부터 추가된다. 새 KG 버전도 기존 템플릿에 자동 반영되지 않는다.

## 전처리의 의미

v1의 빌드 시점 정규화 선택은 v2에서 **검수한 추출 규칙의 명시적 변환**으로 옮겼다.
문서별 수정은 해당 적용 건에만, 양식 공통 수정은 새 템플릿 버전에 저장한다.
선택한 프리셋의 이름뿐 아니라 연산 배열을 버전에 고정하므로 YAML이 바뀌어도 과거 추출 의미는 바뀌지 않는다.
원문과 정규값, 원본 단위와 목표 단위는 각각 보존한다.

지원 연산: `trim_text`, `strip_thousands`, `split_unit_suffix`, `percent_to_ratio`, `automatic`.
숫자는 Decimal 문자열로 유지한다. 잘못된 천 단위 그룹·지원하지 않는 연산은 오류다.
단위 접미사를 분리해도 실제 단위와 목표 단위가 다르면 실패한다. `%` → 비율은 목표 단위를 비우거나 `1`로 지정한다.
자동 정규화는 정해진 공백·천 단위·단위 접미사 정리이며 문서 의미를 추측하는 모델이 아니다.
CSV는 `data` 테이블을 스트리밍하며 manifest·필드 스키마·lineage 전체가 필요하면 SQLite를 사용한다.

## 검증 경로

`tests/test_v2_runtime.py`: 실제 XLSX, 필터, CSV/SQLite 업무키·정확한 소수, 검수 복원/CAS,
트리의 접힌 자식과 제외/재선택, KG 단건 발행/충돌, 전처리 스냅샷, OpenAPI 계약.
`frontend/tests/restoration.test.tsx`: 브랜드/탭 순서·필터·미선택 안내·프리셋 저장·소스 페이지 순회·검수 승인.

`e2e/v2/workbench.spec.ts`: 기본 진입 → 문서 필터 → 원본 → 검수 → 병합·복수 영역 오버레이 →
범위 이동·확대 → 승인·추출 → 결과 페이지 → 개념 체크 → DB 생성 → CSV/SQLite 실제 파일 →
lineage의 다른 시트 단위 위치 이동. 가상 문서만 사용하고 임시 작업 공간을 정리한다.
실행 방법은 [E2E 안내](../../e2e/README.md)를 따른다.

로컬 검증: 백엔드 **153개 통과**(subtest 5개, 기존 라이브러리 경고 4개),
컴포넌트 **11개 통과**, TypeScript/Vite 프로덕션 빌드 성공.
트리 선택 소스 조회와 실제 XLSX 전처리의 추가 확인 2개도 통과했다.
Playwright는 테스트 등록을 확인했으며 브라우저 실행 결과는 CI에 별도로 기록한다.

이전 클라우드 브라우저의 로컬 URL 차단은 유지하며 우회하지 않았다.
브라우저 회귀 실행은 저장소의 GitHub Actions에서 수행하며 실행 결과는 해당 커밋의 Actions 기록으로 확인한다.
컴포넌트 검사와 Playwright 테스트 등록 확인은 실제 브라우저 통과와 구분한다.

## 실제 DRM과 후속 범위

확인한 환경은 Linux이며 실제 DRM SDK·등록된 factory·고정 Reader 리비전이 없다.
일반 XLSX 또는 `tests/v2_reader_fixture.py`의 대역을 실제 DRM PoC 완료로 계산하지 않는다.

제품 SDK를 연결한 환경에서 다음 명령으로 권한·버전·native 렌더 좌표 계약을 확인할 수 있다.

```bash
python -m kg.v2.reader_probe --ws <workspace> --provider protected-reader \
  --source-ref <approved-reference> --sheet-index 0 --range A1:L20
```

`KG_V2_READER_FACTORY`, `KG_V2_READER_REVISION`, 제공자 사용자 문맥을 서버에서 설정한다.
점검 결과에는 원문·문서명·토큰·이미지를 쓰지 않는다. 이 명령은 렌더 계약만 확인하며
`extraction_verified: false`를 명시한다. 실제 추출 정확도와 원본 충실도는 제공자 SDK·승인된
DRM 샘플로 별도 검증해야 한다. 현재 미설정 환경의 실행 결과는 `DRM_READER_REQUIRED`다.

v1 데이터 자동 마이그레이션, PostgreSQL+AGE, DVC 자동 연동, KG 그래프 캔버스,
겹친 템플릿 동시 overlay, 재크롤링 정책, watch 자동 등록은 후속 범위다.
기존 기능 목록과 동등하다고 주장하지 않으며, 각각 v2 버전·권한·재검수 정책에 맞춰 설계한다.
